## Recommendations for NestSelf

1. **Use eu-central-1 as both control and media region.** It supports both roles, keeping all API calls, meeting metadata, lifecycle events, and media processing within Frankfurt. This satisfies data residency requirements for Serbia/Hungary (EU). Hard-code `MediaRegion: 'eu-central-1'` rather than using the nearest-region endpoint, since all your users are in central/southeast Europe. *(CORE-09, CORE-10, CORE-11)*

2. **Use the `chime-sdk-meetings` namespace exclusively** (`@aws-sdk/client-chime-sdk-meetings`). The legacy `chime` namespace is deprecated, us-east-1-only, and lacks echo reduction, attendee capabilities, and media replication. *(CORE-01, CORE-37, CORE-39)*

3. **For 1:1 consultations (therapy, legal, financial), use a standard-definition meeting with echo reduction enabled.** Set `Audio.EchoReduction: 'AVAILABLE'`, leave Video at HD (720p default). 250-attendee cap is irrelevant for 1:1, but HD video at 720p is fine for a talking-head consultation. Echo reduction helps when either party uses speakers instead of headphones. *(CORE-05, CORE-06, CORE-26)*

4. **For webinars, use media replication** (primary + replica meetings). The presenter joins the primary meeting. Employees join replica meetings with `Capabilities: { Audio: 'Receive', Video: 'Receive', Content: 'Receive' }` (view-only). They cannot see each other's video. To ask a question, promote the attendee to the primary (or use data messages for text Q&A). This scales to thousands with a limit increase. Recording captures the primary only. *(CORE-08, CORE-20, CORE-41, CORE-42)*

5. **For group workshops (<=25), use a standard meeting.** All 25 attendees can publish video simultaneously. Use priority-based downlink policy to manage which tiles are visible when bandwidth is constrained. Content sharing supports 2 simultaneous sharers. *(CORE-14, CORE-15, CORE-32)*

6. **Mobile strategy: use a WKWebView / Chromium WebView with the JS SDK for the Expo app, not a native Chime SDK wrapper.** The WKWebView path gives audio + video without ejecting from Expo or building a native module. Content sharing is not available in mobile WebViews, but for the employee side of a consultation this is acceptable (the expert shares from desktop). This avoids the risk of the unmaintained React Native demo and the incomplete third-party Expo module. If screen sharing from mobile becomes a product requirement later, revisit with a native module via Expo Modules API. *(CORE-23, CORE-34, CORE-35, CORE-36)*

7. **Implement `POST /appointments/:id/join` as the single join entry point** (per D-22). The server creates the meeting (or returns the existing one via the idempotent `ClientRequestToken` keyed to the appointment id), creates/retrieves the attendee, and returns the `Meeting` + `Attendee` (including `JoinToken`) to the client. The join token has no TTL, so the client can reconnect after drops. Call `DeleteMeeting` when the session is over or after the scheduled window. *(CORE-02, CORE-17)*

8. **Request a concurrent-meeting-limit increase** if you expect more than 250 simultaneous meetings in eu-central-1. Also request a media pipeline limit increase (default is 10 in Frankfurt) if you plan to record webinars or consultations. API rate limits (10 rps default) should be adequate for early traffic but scale automatically with the concurrent meeting limit. *(CORE-18, CORE-19, CORE-12)*

9. **Recording requires opt-in:** use media capture pipelines, not client-side recording. The pipeline records into your S3 bucket (keep it in eu-central-1). Only the first 25 video tiles are captured. For 1:1 consultations with consent, create the pipeline after both participants confirm. For webinars, record the primary meeting only. *(CORE-42)*

10. **Network configuration documentation for client companies:** UDP 3478 and TCP 443 to `*.chime.aws` (99.77.128.0/18). Voice Focus and background blur need TCP 443 to `*.sdkassets.chime.aws`. If corporate firewalls block UDP, the SDK falls back to TLS/443 automatically. *(CORE-30)*

## Could not verify / open questions

1. **Join token TTL**: The docs say it is valid for the meeting's lifetime, but do not state an explicit cryptographic expiry. No evidence of a fixed clock-based TTL. Needs a practical test to confirm a token issued hours before the meeting starts still works.

2. **HD session attendee cap: 25 vs 100**: The FAQ says "100 attendees in a high-definition session" but the feature docs and pricing page consistently say 25. The 25 figure appears authoritative (it matches the API validation and the pricing tier). The FAQ may be stale. Verify against current Service Quotas console.

3. **`amazon-chime-sdk-js` React 19 direct compatibility**: The *component library* (wrapper) confirmed React 19 support in v3.12.0. The core JS SDK itself is framework-agnostic (no React peer dep), so React 19 compatibility is not a direct concern for it, but this should be verified in integration testing.

4. **Expo iOS WKWebView audio/video reliability**: The browser support table lists WKWebView 14.3+ for audio+video, but real-world performance in an Expo-managed WebView (especially background behavior, microphone access lifecycle on iOS, and camera hardware access) needs end-to-end testing on a physical device.

5. **`BatchUpdateAttendeeCapabilities` name mismatch**: The brief named `BatchUpdateAttendeeCapabilities`, but the actual API is `BatchUpdateAttendeeCapabilitiesExcept` (updates all attendees *except* the listed ones). There is no `BatchUpdateAttendeeCapabilities` that takes an include-list. Confirm this is acceptable for the webinar promotion use case.

6. **Bandwidth requirements for Serbia/Hungary**: Real-world mobile network quality in rural Serbia may be below the ~650 kbps needed for video. Simulcast and priority-based downlink help, but audio-only fallback behaviour under very constrained bandwidth (<100 kbps) should be tested.

7. **Carrier Voice Focus deprecation scope**: Ended 2026-06-30, but this is distinct from the client-side Amazon Voice Focus noise suppression in the JS/mobile SDKs. Confirm that client-side Voice Focus continues.

8. **Content share audio on iOS native SDK**: A GitHub issue (#300 on amazon-chime-sdk-ios) reports that screen-shared video audio is not transmitted. Status of fix is unknown.
