# ADR 0002: The employee listening module, its boundaries and its defaults

**Status:** Accepted, 2026-11-01; revised 2026-11-02 (D-EL-14 added).
**Context:** `docs/tasks/employee-listening/spec.md` (version 1.0, 31 October 2026): recurring employee surveys with protected reporting, an optional human workplace review and an employer-anonymous feedback channel. Section 1.2 of the spec asks the implementation to record material departures and the reasons in the repository's decision log; this record holds them together with the choices the spec left to the implementation.

## Decisions

1. **D-EL-01 Three modules, one restricted domain.** `apps/api/src/listening` owns configuration, questionnaire versions, cycles, participation, finalization, aggregates, disclosure, reports, exports, the review offer and the listening jobs. `apps/api/src/feedback-cases` owns organizational feedback cases and is a restricted domain modelled on `professional`: every case is a confidential resource, access goes through CASE assignments or the reporter's own scope, a denial answers 404, and the reporter's identity lives in a table (`feedback_case_reporters`) that no handler, employer or staff path joins. `apps/api/src/workplace-reviews` owns requests, versioned scopes, engagements, sharing grants, human report versions, actions and follow-up. Tables live in one PostgreSQL database with row-level security, one schema file per module.
2. **D-EL-02 Scores are integers in tenths of a percent, computed once.** `scoreTenths`, `classifyScore`, `trendTenths`, `isStale` and `planSuppression` in `@nestself/contracts` (`listening-scoring.ts`) are the only implementations; the API persists the result per cell and the web apps only format what the API classified. Integer arithmetic gives the spec's decimal round-half-up (`59.95 -> 60.0`) without binary floating-point drift between backend and frontend.
3. **D-EL-03 No availability module exists, so the coordinator proposes the times.** The review coordinator proposes one to three windows on the engagement and the employer requester confirms one. Provider capacity is protected by a per-reviewer transaction advisory lock and an overlap check against the reviewer's non-final appointments, so two confirmations cannot both succeed. A real availability service would replace the proposal step, not the confirmation.
4. **D-EL-04 No payment integration exists, so acceptance records authority, not money.** Accepting a scope binds its immutable version, checks the approver's spending ceiling through the grant engine (`workplace_reviews.scope.accept` with the scope's amount as the resource amount) and creates the engagement. It creates no charge, no reservation and no funding entry; the appointment's `fundingRef` stays null. When a service has no configured price the request shows "Request a quote".
5. **D-EL-05 Notifications are emails.** The platform has an outbox table but no in-app notification API, so the module notifies through `Mailer` after commit with neutral bodies and authenticated links. In-app notifications can be added when that API exists.
6. **D-EL-06 Case actions are `feedback_case.*`.** `feedback.submit` already means product feedback in the catalogue, so the spec's `feedback.*` suggestions are implemented as `feedback_case.create.self`, `feedback_case.read.self`, `feedback_case.reply.self`, `feedback_case.handle` and `feedback_case.assign`, all in `CONFIDENTIAL_ACTIONS`.
7. **D-EL-07 Self-access after membership end is a known gap.** The engine refuses any personal context without an ACTIVE membership, so a former employee cannot read their own feedback cases (spec PRI-05). Changing that rule is an authorization-strategy decision; it is listed in `docs/tasks/employee-listening/dev.md` as open.
8. **D-EL-08 The sample seed publishes questionnaire version 1.** The seed is fictional demo data (sample-data rule) and refuses production; in production the first version is created as a draft and published by a content owner through the admin screen.
9. **D-EL-09 Exports are generated on request.** The CSV is built from the same sanitized cells as the dashboard, on an authorized request behind the `export` step-up class, audited, and streamed; nothing is stored, so there is no file to expire or revoke.
10. **D-EL-10 The sensitive route is a configuration gate.** NestSelf operations switch `feedbackSensitiveEnabled` on for a client only after the organization has a validated sensitive route (primary, independent alternate, operating hours, response target, escalation note). Without both, the composer shows the organization's ordinary route and the alternative process text, never an unstaffed inbox.
11. **D-EL-11 Reviewer qualification.** A workplace reviewer is an expert with an APPROVED `expert_credentials` row whose `serviceCategory` is `workplace_review`, holding the `workplace_reviewer` template; assignment gives a CASE assignment on the engagement only. A therapist without that credential is not a workplace consultant.
12. **D-EL-12 The booked meeting is an appointment.** Booking creates an `appointments` row with `serviceCategory = 'workplace_review'`, the reviewer as the expert and the employer requester as the employee participant, so reminders, the call room and cancellation reuse the consultations epic. Employee clinical appointments are told apart by the category, and the employer's private allowance is never involved.
13. **D-EL-13 Disjoint cohorts only.** Reporting cohorts are the company and the departments directly under the company root (a member's primary department is the ancestor of their org unit at that level; members without one form the `unassigned` cohort). Teams, project groups and arbitrary filters are not reporting cohorts in the pilot.

14. **D-EL-14 Escalation never returns a case to the primary recipient.** The hourly `feedback.escalate-overdue` job moves a case the primary let pass its response target to the route's alternate, when that person is still an eligible handler, and tells them. A case the reporter deliberately routed to the alternate, because the matter concerns the primary (spec FBK-03), is never moved back: it is marked escalated and its handler is reminded instead. A hand-over by a handler follows the same rule on the server (`same_handler`, `handler_not_eligible`).

## Consequences

- Scores, bands, cohort minimums and freshness are policy versions locked at cycle launch; changing them affects future cycles only.
- The feedback domain shares the engine's confidential-resource rules with the professional domain, so a platform administrator, support operator or employer administrator cannot reach a case through a generic viewer.
- Workplace review scheduling depends on the coordinator until an availability service exists; payments stay outside the platform.
- Changing any of these decisions means a new revision of this record.
